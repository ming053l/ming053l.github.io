TL;DR: Watermark AI-generated text, then check it with the original model and a secret key. No saved generation history needed.

The idea

Same words. A different kind of watermark.

A watermark can help a model provider recognize text it generated. Many methods do this by making certain words more likely. ReplayMark instead uses how the model’s predictions change when some earlier context is hidden.

While generating text, a secret key guides which of these responses to favor. To check a document later, the provider hides the same context and asks the original model again. If the responses agree with the key more often than chance would explain, that is evidence of the watermark.

  • Token watermark. A hash turns earlier words and a secret key into a repeatable choice of preferred words. Making those words more likely leaves a pattern that can be checked later.
  • Ordinary diffusion model. The model fills missing words in a flexible order. More confident predictions can be filled first, rather than always writing from left to right.
  • ReplayMark. Keep that filling order, but guide word selection using the model’s response to hidden context. The verifier needs the original model to recognize this signal.
Technical detail: compare the generation procedures

Generic dLLM Decoding

Require: prompt x, model θ, decoder F

1  y ← masked continuation
2  while masked positions remain:
3    p ← model predictions for y
4    J ← positions chosen by F
5    for i in J:
6      v ← reference token draw from pᵢ
7      yᵢ ← v
8  return y

ReplayMark: Probe and Write

Require: same x, θ, F; key K, R, κ

1  y ← masked continuation
2  while masked positions remain:
3    p ← model predictions for y
4    J ← same reference schedule F
5    for i in J:
6      rebuild probes; select carrier
7      if carrier: consult keyed direction
8        try ≤ R plausible matching draws
9        otherwise: unchecked fallback draw
10     else: reference token draw
11     yᵢ ← selected token
12 return y

Conceptual pseudocode. Carriers are selected independently of the keyed direction; accepted candidates must have probability at least κ times the live maximum. Verification re-masks the finished text, rebuilds the probes and carriers, and applies the exact binomial-tail test. See the paper for the complete construction.

How it works

Write it once. Recognize it later.

The key idea is to repeat a small prediction experiment—first while generating, then while checking the finished text.

  1. 1

    Hide some context

    Ask the model to predict with different parts of the earlier text hidden. These queries are called probes. Keep positions where the model supports both response directions; these usable positions are called carriers.

  2. 2

    Choose a matching word

    Only after choosing a carrier does the secret key set a preferred direction. Draw a plausible word that matches it. If the limited retries fail, take an ordinary draw. The order of filled positions stays the same.

  3. 3

    Repeat the check

    The verifier hides the same context in the finished text and repeats the probes with the original model. Count the responses that match the key, then test whether chance can explain that many matches.

From responses to evidence

Could those matches happen by chance?

A match on its own proves little. Without the secret key, each usable response has a 50–50 chance of matching. Many matches together are harder to explain by chance. ReplayMark uses an exact statistical test to quantify that evidence.

Scope & limitations

What you need—and where it breaks

ReplayMark is for providers or auditors who can access the original model. It is not a model-free detector for arbitrary text.

Access to the original model

Checking requires the same model checkpoint, numerical precision, key, and probe settings. A 512-token document takes 144 model calls—about 27 seconds on the TITAN RTX used in the paper.

Rewriting can erase the signal

In the reported editing study, detection holds up better when edits stay together. Scattered edits hurt more, and full paraphrasing removes detection. Short fragments also provide less evidence.

A positive result supports agreement with the registered watermark. It does not identify who requested the text or label individual passages. The study covers two models and small test cohorts; broader validation is still needed.
